# tools/stack_edges.txt - declared indirect-call targets for tools/stack_budget.py
#
# Every entry here resolves ONE class of unresolved `bl <bx-rN thunk>` site the call-graph
# walker in stack_budget.py finds inside the named caller. These are genuine runtime
# function-pointer dispatches (BoxSource's per-source hooks, source/pdna_box.h:19-63, and
# the AppCommitFn `commit` parameter threaded through app_mon_menu/app_paste_gb_merge/
# app_take_item/app_give_item/app_commit_with_dex, source/pdna_app.h:52) — a disassembly
# walk cannot see through a value loaded from a struct field or a stack-spilled parameter,
# so THIS FILE is the ground truth, derived by reading every assignment site in source
# (2026-09-10, BACKLOG #84b).
#
# D7 (BACKLOG #84b fourth pass): `-fstack-usage` is unconditional in the Makefile's base
# CFLAGS (set before any PDNA_TARGET-specific `ifeq` branch, so every one of artless/
# normal/delta compiles with it) -- the measured ELF IS the shipped ELF, not a separate
# instrumented build. An earlier pass's "the walker's number might be 4 B off .rodata
# against a non-instrumented build" caveat is therefore moot: there is no non-instrumented
# build to be off against.
#
# FORMAT (D1 fix -- BACKLOG #84b review found the OLD `caller -> impls` shape exempted
# every indirect site in a function once ANY one class was declared for it; a new,
# undeclared function pointer in a multi-class caller like pdna_box passed silently):
#
#   Struct.field @OFFSET -> impl1 impl2 ...
#     A struct-field dispatch. stack_budget.py resolves each site to the offset its
#     `ldr rN, [rY, #OFFSET]` loads (the instruction immediately feeding the `bl <bx-rN
#     thunk>`) and only exempts a site whose OFFSET is declared here -- an eleventh,
#     undeclared BoxSource field pointer does NOT inherit exemption from the other ten.
#     OFFSET is cross-checked at guard time against the struct's OWN header (computed
#     with the same natural ARM EABI layout GCC uses) -- a stale offset here (header
#     changed, this file didn't) is a FATAL, not a silent pass.
#
#   caller argsites=N -> impl1 impl2 ...
#     A parameter-threaded dispatch (no struct field to key on -- AppCommitFn's `commit`
#     argument). N is the number of such sites in `caller` TODAY, counted by reading the
#     source; if the disassembly's count ever differs (a site appeared or vanished), the
#     guard FAILS naming the caller instead of silently re-using a stale exemption.
#
# BoxSource field offsets (source/pdna_box.h, natural ARM EABI packing, verified against
# this build's own objdump -- e.g. `ldr r3,[r6,#20]` before pdna_box's `records()` calls,
# `ldr r3,[r3,#60]` before its `note_box()` calls):
#   nboxes=0 last_box_is_party=4 start_box=8 is_bank=12 has_start=13 wp_count=16
#   records=20 menu_block=24 get_name=28 set_name=32 get_wp=36 set_wp=40 can_edit=44
#   commit=48 mark_dirty=52 note_add=56 note_box=60 capacity=64
#
# Assignment sites (grep that reproduces this list: `grep -rn "\.records *=\|\.get_name *=\|
# \.set_name *=\|\.get_wp *=\|\.set_wp *=\|\.can_edit *=\|\.commit *=\|\.mark_dirty *=\|
# \.note_add *=\|\.note_box *=\|\.capacity *=" source/` finds exactly these and no others --
# checked against source/pdna_bank.c, source/pdna_gen12.c, source/pdna_main.c, the only
# three files that ever populate a BoxSource):
#   records    -> pdna_bank.c:295 pdna_gen12.c:565 pdna_main.c:8509  (3 sources)
#   get_name   -> pdna_bank.c:297 pdna_gen12.c:567 pdna_main.c:8511
#   set_name   -> pdna_bank.c:298 pdna_gen12.c:568 pdna_main.c:8512
#   get_wp     -> pdna_bank.c:299 pdna_gen12.c:569 pdna_main.c:8513
#   set_wp     -> pdna_bank.c:300 pdna_gen12.c:570 pdna_main.c:8514
#   can_edit   -> pdna_bank.c:301 pdna_gen12.c:571 pdna_main.c:8515
#   commit     -> pdna_bank.c:302 pdna_gen12.c:572 pdna_main.c:8516
#   mark_dirty -> pdna_bank.c:303 pdna_gen12.c:573 pdna_main.c:8517
#   note_add   -> pdna_main.c:8518 (pcsrc_note_add; the bank leaves it NULL, the GB source
#                 sets it to 0 explicitly, pdna_gen12.c:574 -- every call site in pdna_box.c
#                 is `if (src->note_add) src->note_add(...)`, so only the one live
#                 implementation matters)
#   note_box   -> pdna_gen12.c:575 (gbsrc_note_box; guarded the same way, only the GB
#                 source sets it -- pdna_bank.c/pdna_main.c never do)
#   capacity   -> pdna_gen12.c:576 (gbsrc_capacity; guarded the same way)
#
# `AppSrcOps`/`g_src_ops` (k_gb_ops/k_gb_ops_ro, pdna_gen12.c:2429/2452) is a SEPARATE
# dispatch table but is not reached from any function on the top-5 chains today
# (app_mon_menu's RO_VIEW/RO_MOVE/RO_RELEASE/RO_PASTE/RO_CREATE cases call it, but those
# cases are not on the deepest-chain path) -- add it here the day a chain grows to include
# one of those cases; the guard's per-SITE blind-spot check will name the function if that
# ever happens instead of silently trusting a stale list.
#
# WHY A NAMED IMPLEMENTATION MISSING FROM THE ELF IS A WARNING, NOT A FATAL (BACKLOG #84b,
# third pass, 2026-09-10): if one of the impl names listed after a `->` above is not found
# in the built ELF's disassembly (stack_budget.py's own "names implementation(s) not found"
# message -- seen live for `fused_gb_slice_read`, a declared implementation this build no
# longer links), that only means the reachable call graph SHRANK -- one fewer concrete
# function the walker could have attributed a dispatch to. It can never make the guard's
# worst-case total an UNDER-count: every other declared implementation for that same site
# is still exempted and still contributes its own (measured or estimated) frame size to
# the deepest-chain search, so the bound the guard reports is still sound, just possibly
# no longer tight against a function that no longer exists to be on any chain. Treating it
# as FATAL would make the guard fail every time an implementation is deleted, refactored
# away, or link-time-GC'd for an unrelated reason -- exactly the kind of noise that trains
# people to stop reading FATALs. Compare: an offset that no longer matches the struct
# header (verify_field_declarations) IS fatal, because that direction genuinely risks an
# under-count.
# D9 (BACKLOG #84b fifth pass): this section used to also claim "a NEW, UNDECLARED
# implementation IS fatal" here -- false at the time this was written: nothing in the
# walker ever looked for a function whose address is taken (stored into a struct field or
# assigned to a global) but never reached through the declared field/argsites classes
# above, so a brand-new implementation installed into an ALREADY-declared class was
# completely invisible, not caught. D1 (own commit, same pass) adds the address-taken
# sweep that makes this true again: a NEW, UNDECLARED implementation -- one whose address
# is taken anywhere in the linked image but that no declaration names, no ordinary
# reachability reaches, and no `isr`/`addrtaken-ok` line excuses -- IS now fatal, exactly
# the direction that genuinely risks an under-count, same as the offset-mismatch case
# right above it.
